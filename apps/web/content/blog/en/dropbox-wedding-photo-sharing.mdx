Dropbox can collect wedding photos without putting every guest inside a shared
folder. A file request gives contributors an upload page and places the files
in a folder controlled by the couple. It is practical for collecting originals,
but it does not create much of an event experience by itself.

## The safest Dropbox setup

Create one destination folder, then create a file request for it. Share the
request link as a QR code and test it in a private browser before printing. A
guest should be able to choose files, see a clear completion message and avoid
seeing the couple's wider Dropbox account.

Do not share an editable folder unless guests genuinely need to browse, rename
or remove other files. A file request keeps contributor permissions narrower.

## Plan storage before the wedding

Estimate volume using the guest count, expected participation and whether video
is allowed. Fifty guests uploading ten modern phone photos can already create
several gigabytes; video grows far faster. Check the receiving account's free
space and leave a safety margin.

After the upload period:

1. download the complete folder;
2. verify that large files open correctly;
3. remove duplicates without overwriting originals;
4. keep a second copy outside Dropbox;
5. close or replace the public request link.

## Where Dropbox works well

Dropbox is a good fit when original files, familiar folder storage and late
uploads matter. It also works when only a small group, such as the wedding
party, will contribute.

Its weakness is participation. Guests must select files and complete an upload
task, usually after taking photos elsewhere. There is no finite roll, delayed
reveal or wedding-specific gallery unless another tool supplies it.

For a guest-facing experience, compare Dropbox with a
[browser-based wedding photo upload](/en/wedding-guest-photo-upload) or a
[digital disposable camera](/en/digital-disposable-camera-for-weddings).
